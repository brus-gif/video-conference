# 会议多宫格显示项目 — 开发计划

> 项目目标：参照产品图实现一套"会议多宫格显示"应用。核心需求是**宫格数量随成员数量动态调整**。
> 当前进度：**阶段一（界面原型机）已完成；阶段二（本地功能落地）核心项已完成，收尾项进行中；阶段三（联网会议）信令服务、客户端信令接入、媒体传输（WebSocket 帧中继版摄像头/麦克风/屏幕共享）已完成，WebRTC 真视频为后续里程碑**。

---

## 一、总体技术选型

| 层面 | 选型 | 说明 |
|------|------|------|
| 语言 | C++17 | 跨平台、性能好、适合音视频 |
| UI 框架 | Qt 6 Widgets（msvc2022_64） | 成熟稳定，QPainter 自绘便于做自定义宫格 |
| 构建 | CMake + Ninja | 主流、可扩展 |
| 后续音视频 | Qt Multimedia / WebRTC（libwebrtc / GStreamer） | 阶段三后评估 |
| 通信 | 暂不涉及（原型） | 后续可接 WebSocket / 自研信令 |

## 二、阶段划分与里程碑

```
阶段一（已完成）  界面原型机 —— 静态 UI + 动态宫格逻辑演示
    ↓
阶段二（进行中）  本地功能落地 —— 真实视频采集、宫格内渲染、交互完善
    ↓
阶段三（待启动）  联网会议 —— 信令 + 音视频传输 + 多人实时
    ↓
阶段四（待启动）  性能与产品化 —— 大并发优化、稳定性、发布
```

### 阶段一：界面原型机 ✅（本次已完成）

- [x] 参照产品图搭建整体界面：顶栏、宫格区、成员面板、底部控制栏、聊天面板
- [x] 动态宫格核心算法（`GridManager::calcGrid`）：
  - 1 → 1×1，2 → 1×2，3~4 → 2×2，5~6 → 3×2，7~9 → 3×3，…
  - 通用：`列数=⌈√n⌉`，`行数=⌈n/列数⌉`
- [x] 宫格组件 `VideoTile`：头像、名字胶囊、麦/摄像状态、说话/选中高亮、摄像头关闭剪影、空格占位
- [x] `GridContainer` 两种视图：宫格视图 / 演讲者视图
- [x] 成员增减交互：滑块(1~49)、快捷按钮(1/4/9/16/25)、添加/移除
- [x] 运行验证：4 人 → 2×2、9 人 → 3×3、16 人 → 4×4（截图见 `docs/screenshots/`）

### 阶段二：本地功能落地（进行中，已完成大部分核心项）

| # | 任务 | 说明 | 状态 |

| 6 | 设置面板 | 摄像头/麦克风设备选择、视频填充模式、模拟画面帧率；分辨率/回声消除待加 | 🔶 部分 |
| 7 | 状态持久化 | 记住会议设置、最近会议记录 | ⬜ 待办 |

### 阶段三：联网多人会议（预计 4~6 周）

| # | 任务 | 说明 | 状态 |
|---|------|------|------|
| 1 | 信令服务 | WebSocket 信令（建会/入会/麦控/共享/聊天），C++/Qt `QWebSocketServer` 自研（`server/`），协议见 `docs/信令协议.md` | ✅ 已完成（冒烟测试 17/17） |
| 2 | 媒体传输 | WebRTC（SFU 架构）为后续里程碑；已先用 **WebSocket 二进制帧中继** 实现摄像头/麦克风推送（JPEG+PCM，能看能听，`server/` 透传 + `SignalingClient::sendMedia`） | 🔶 中继版已完成，WebRTC 待启动 |
| 3 | 成员管理真实化 | 客户端接入信令：入会/离开实时刷新宫格（`SignalingClient` + `MainWindow` 联网模式） | ✅ 已完成 |
| 4 | 参会者列表同步 | 麦/摄像/共享状态双向同步（`set_state`/`set_share` → `member_updated` 广播） | ✅ 已完成 |
| 5 | 屏幕共享 | 桌面抓帧 → JPEG → 中继 → 远端宫格显示（`QScreen::grabWindow` + `QTimer` 4fps）；演讲者视图大画面为后续 | 🔶 帧中继版已完成 |
| 6 | 消息聊天 | 收发消息（已完成）；@某人、系统通知 | 🔶 部分（收发完成） |
| 7 | 弱网处理 | 码率自适应、重连、丢包统计 | ⬜ 待启动 |

> 阶段三已交付：信令服务端（`server/`）+ 客户端联网接入（`src/SignalingClient.*`、`MainWindow` 联网模式）+ **媒体传输（摄像头/麦克风/屏幕共享的 WebSocket 帧中继）**，测试见 `tests/tst_signalingclient.cpp`。WebRTC 真视频/低延迟为后续里程碑。

## 三、风险与决策点

| 风险 | 影响 | 对策 |
|------|------|------|
| WebRTC 引入复杂度 | 阶段三周期 | 先用成熟 SFU（LiveKit）快速打通，再按需自研 |
| 大宫格渲染卡顿 | 体验 | 阶段四专门做渲染性能专项；预先用 `QTimer` 控制降帧 |
| 视频比例与宫格适配 | 观感 | 提供"填充/裁剪"两种模式，默认裁剪填充 |
| 跨平台兼容 | 发布范围 | Qt 已跨平台，媒体层用抽象接口隔离 |

## 五、验收标准

- **阶段一（原型）**：① 打开应用默认展示 4 人 2×2 宫格；② 调整成员数量，宫格行列实时变化；③ 宫格/演讲者视图切换正常；④ 麦/摄像开关状态正确联动。
- **阶段二（本地功能）**：① 主持人宫格显示真实摄像头画面，远端成员显示模拟画面；② 视频填充模式可切换；③ 摄像头关闭即时显示剪影、不再显示残留画面；④ `calcGrid` 单元测试全量通过。
- **阶段三（联网）**：两终端可加入同一会议，互相看到画面、听到声音，成员增删实时反映宫格变化。
